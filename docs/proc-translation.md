# PROC translation

Assembly processes are primitive coroutines. In C, a process entry is a function
that takes a `PROC *p`. A process may suspend in `SLEEP`, and execution must later
resume at the instruction immediately after that `SLEEP`.

## Resume stack

Each `PROC` owns:

```c
u32 resume_states[PROC_RESUME_STACK_SIZE];
u32 current_resume_depth;
u32 yielded;
```

`PROC_RESUME_STACK_SIZE` is currently 10.

Before calling the root process function, the dispatcher sets:

```c
p->current_resume_depth = 0;
p->yielded = 0;
```

The root function and every nested coroutine function read and write the resume
state at the current depth through:

```c
PROC_RESUME_STATE
```

Do not access `resume_states` directly outside the process implementation and
macros. Do not clear a resume state after resuming. A later `SLEEP`, `JSRP`, or
`PROC_CONTINUE` overwrites it, and `p->yielded` says whether the current
invocation suspended.

## Function resume dispatch

Every translated coroutine function needs a switch at its beginning. Resume
numbers need only be unique within that C function.

```c
static void EXAMPLE_PROC(PROC* p)
{
    switch (PROC_RESUME_STATE) {
    case 0:
        MAME_ASSERT_FUNCTION_ENTRY();
        break;
    case 1:
        goto PROC_RESUME_1;
    case 2:
        goto PROC_RESUME_2;
    }

    // Function body.
}
```

`PROC_RESUME_n` labels are generated by the `SLEEP`, `JSRP`, and
`PROC_CONTINUE` macros. Do not write a second label manually.

## Translating SLEEP

Translate:

```asm
SLEEP 1
```

as:

```c
SLEEP(1, 1);
```

The second argument is the resume number. Conceptually, the macro expands to:

```c
PROC_RESUME_STATE = 1;
p->yielded = 1;
PRC_SLEEP(p, 1);
return;
PROC_RESUME_1:
```

Therefore, execution returns from the C function when the process sleeps. On a
later dispatch, the switch jumps to the macro-generated label and execution
continues after the `SLEEP` statement.

Example loop:

```c
static void WATCHER(PROC* p)
{
    switch (PROC_RESUME_STATE) {
    case 0:
        MAME_ASSERT_FUNCTION_ENTRY();
        break;
    case 1:
        goto PROC_RESUME_1;
    }

WATCH_LOOP:
    UPDATE_WATCHER();
    SLEEP(1, 1);
    goto WATCH_LOOP;
}
```

Any local value needed after `SLEEP` must be stored in the function-specific
`PROC_CONTEXT`. Ordinary C locals do not survive suspension.

## Validation markers

Every translated coroutine function must call `MAME_ASSERT_FUNCTION_ENTRY()`
from `case 0` of its resume switch. Do not place it after the switch: that would
assert a new function entry when dispatch is only reconstructing a suspended
call path.

A function entered through `JSRP` or `PROC_CONTINUE` should also identify the
assembly entry point with an ordering marker:

```c
case 0:
    MAME_ASSERT_FUNCTION_ENTRY();
    MAME_ASSERT_ORDERING("CHILD_PROC");
    break;
```

`MAME_ASSERT_ORDERING(message)` writes an `ordering message` event into the MAME
trace at the next annotated assembly instruction. The port consumes that event
at the marker and compares the message. This checks that nested coroutine calls
reach the expected assembly code in the expected sequence, including extracted
C helpers whose function name does not exist in the assembly symbol map.

## Nested coroutine calls

`JSRP` and `PROC_CONTINUE` call another coroutine at the next resume depth:

```c
JSRP(CHILD_PROC, 2);
```

Conceptually, it:

1. Saves resume state `2` at the caller's current depth.
2. Defines the caller's `PROC_RESUME_2` label at the call site.
3. Increments `current_resume_depth`.
4. Calls `CHILD_PROC(p)`.
5. Restores the caller's depth when the child returns.
6. Returns from the caller too if the child yielded.

The caller's top-level switch must contain:

```c
case 2:
    goto PROC_RESUME_2;
```

The child has its own resume switch. Because it runs at the next depth, its
resume numbers do not conflict with the caller's numbers.

If a child sleeps, `yielded` propagates through every active nested coroutine
call. On the next root dispatch, each caller's switch reconstructs the call
path until the sleeping child reaches its own resume label.

## Assembly JSRP versus a cross-function branch

The two C macros have identical resume behavior but preserve different assembly
meanings:

- Use `JSRP` only for an actual assembly `JSRP` instruction.
- Use `PROC_CONTINUE` when a branch or ordinary call needs the same nested
  resume machinery because its target is a suspendable translated `PROC`
  function.

An actual assembly coroutine call continues in the caller:

```asm
JSRP CHILD_PROC
; caller continuation
```

```c
JSRP(CHILD_PROC, 2);

// Caller continuation.
```

An assembly branch into another translated `PROC` function is a tail call. It
must not continue at the instruction after the branch:

```asm
BU CHILD_PROC
```

```c
PROC_CONTINUE(CHILD_PROC, 2);
return;
```

Use these rules:

- A branch to a label in the same C function is a `goto`.
- A branch to another translated `PROC` function is
  `PROC_CONTINUE(target, state);` followed by `return;`.
- An ordinary assembly call to a suspendable translated `PROC` function is
  `PROC_CONTINUE(target, state);` followed by the caller's normal continuation.
- An assembly `JSRP` is `JSRP(target, state);` followed by the caller's normal
  continuation.
- A branch to an ordinary helper that cannot suspend may be a direct C call
  followed by `return;`.
- Actual process operations such as `PRC_XFER` are separate from these
  coroutine control-flow rules.

The cross-function branch rule applies transitively. If a branch target itself
branches to another coroutine, that edge also needs `PROC_CONTINUE`. This
preserves the full path needed to reach a nested sleep.

For example:

```text
PLYR_INTRO
  -> LOAD_NEW_SELECTION
    -> PLYR_INTRO__ALL_JOINUP_tail
      -> _PLYR
```

If `_PLYR` sleeps, dispatch reconstructs all four functions at successive
resume depths. Do not replace this with direct `p->func` or resume-state
assignments.

## Extracted shared tails

Assembly can branch into a large shared tail from multiple entry points. C
cannot `goto` across function boundaries, so extracting the tail into a helper
is appropriate.

If the tail can suspend directly or transitively, make it a coroutine function
and enter it with `PROC_CONTINUE` from each predecessor:

```c
static void SHARED_TAIL(PROC* p)
{
    switch (PROC_RESUME_STATE) {
    case 0:
        break;
    case 1:
        goto PROC_RESUME_1;
    }

    PROC_CONTINUE(NEXT_COROUTINE, 1);
    return;
}
```

If the tail and everything it calls are guaranteed not to suspend, it may be an
ordinary helper called directly.

## REENTER

`REENTER(fn)` restarts a logical process entry at resume state zero. It is for a
branch such as:

```asm
B BGD_WATCHER
```

when the translation deliberately re-enters that logical entry. It is not a
general arbitrary-state transfer mechanism.

Do not introduce `REENTER_AT`, and do not use direct resume-state assignments to
jump into the middle of another function. Fix the function boundary, extract a
shared tail, or use the nested coroutine model instead.

## Return, DIE, and process identity

Within a nested coroutine, ordinary C `return` represents assembly `RETP` and
returns to the surrounding `JSRP` or `PROC_CONTINUE`.

A root process should normally end by sleeping, dying, or tail-branching into
another coroutine. A plain root return leaves the process active and causes the
dispatcher to invoke it again later.

`DIE()` removes the process. Do not clear resume state before `DIE()`.

Do not assign `p->func` merely because an assembly branch crosses an artificial
C function boundary. The resume stack reconstructs that boundary. Changes to
the root process function are reserved for real process-level behavior such as
an actual `PRC_XFER` translation.

## Process creation

Preserve the assembly macro name in translated C:

- `CREATE(target, pid, ctx)` maps to `PRC_CREATE` and inserts a root process.
- `CREATEC(target, pid, ctx)` maps to `PRC_CREATE_CHILD` and links the new
  process immediately after the current process.

If the assembly explicitly calls `PRC_CREATE_CHILD` rather than using the
`CREATEC` macro, keep the explicit function call in C.

## Translation checklist

Before considering a `PROC` translation complete:

1. Every resume site (`SLEEP`, `JSRP`, or `PROC_CONTINUE`) has a unique resume
   number within its C function.
2. The function's top switch dispatches every resume number to its generated
   `PROC_RESUME_n` label.
3. Every value used after a possible sleep is stored in `PROC_CONTEXT`.
4. Cross-function assembly branches use tail `PROC_CONTINUE` plus `return`.
5. Actual assembly `JSRP` calls continue after the macro rather than returning.
6. No translation directly assigns a resume state to jump into another
   function.
7. No artificial C boundary changes `p->func`.
8. Nested depth does not exceed `PROC_RESUME_STACK_SIZE`.
9. The build, C3X translation check, and MAME validation replay pass.
